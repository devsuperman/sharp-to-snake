# Project Plan: Python Fundamentals (Executable Course)

A study project where every lesson teaches one concept, has exercises that I implement, and automated tests that tell me whether I got them right.

**Who it is for:** a senior .NET engineer learning Python. Every lesson therefore includes a "C# equivalent" section.
**Language:** everything (explanations, docstrings, comments) is in English, which doubles as technical-English practice.

---

## 1. Goals

- [ ] Master the Python fundamentals (syntax, types, collections, functions, classes, exceptions, files, modules, async, type hints).
- [ ] Learn pytest and modern Python project structure (pyproject, venv, packages).
- [ ] Practice technical writing in English.
- [ ] Finish with a mini-project in my own domain (GPS / fleet tracking).

**Success criterion:** every test in `tests/` passes and the mini-project works, written by me, without looking at a solution.

---

## 2. Stack and tooling

| Item | Choice | Reason |
|---|---|---|
| Python | 3.12 or newer | Modern version, good error messages |
| Environment | `venv` (built in) | Simple, no extra dependency |
| Tests | `pytest` | Ecosystem standard |
| Runner CLI | `argparse` (stdlib) | Learn the stdlib, zero dependencies |
| Format/lint | `ruff` | Fast, replaces flake8 + black + isort |
| Types | `mypy` (optional, from lesson 11) | Compare with the C# compiler |
| Editor | VS Code + Python extension (or PyCharm) | Free choice |

## 5. Lesson template

Every file in `lessons/` follows this format:

```python
"""
Lesson NN: <topic>

Goal: <one sentence>.
"""

# 1. CONCEPT  (short explanation in comments)
# 2. EXAMPLES (runnable code: `python lessons/NN_x.py` prints results)
# 3. C# EQUIVALENT (table or comments: "Python X <-> C# Y")
# 4. COMMON PITFALLS (2 or 3 typical traps for people coming from C#)
# 5. EXERCISE (pointer to exercises/exNN_x.py)

if __name__ == "__main__":
    ...  # demos
```

Every file in `exercises/`:

```python
def function_to_implement(x: int) -> int:
    """Describe exactly what it must do, with 2-3 examples."""
    raise NotImplementedError
```

Every file in `tests/`:
- 4 to 8 tests per exercise, covering the normal case, edge cases and errors.
- Use `pytest.mark.parametrize` at least from lesson 03 on (an embedded pytest lesson).

## 6. Detailed curriculum

| # | Topic | Concepts | Exercises (examples) | C# equivalent |
|---|---|---|---|---|
| 01 | Types and variables | `int/float/str/bool/None`, dynamic typing, f-strings, mutability | format a message; convert types safely | `var` vs dynamic, string interpolation, `null` vs `None` |
| 02 | Control flow | `if/elif/else`, `for`, `while`, `range`, `break/continue`, `match` | FizzBuzz; classify values with `match` | `switch` expression, `foreach` |
| 03 | Functions | args, kwargs, defaults, `*args/**kwargs`, multiple returns, closures, lambdas, **the mutable-default trap** | function with kwargs; counter via closure | optional parameters, `params`, `Func<>` |
| 04 | Collections | `list`, `dict`, `set`, `tuple`, slicing, sorting, `collections` | group by key; de-duplicate keeping order | `List<T>`, `Dictionary`, `HashSet`, `ValueTuple` |
| 05 | Comprehensions and iteration | list/dict/set comprehensions, generators, `yield`, `zip`, `enumerate` | filter and transform; batch-reading generator | LINQ (`Select/Where`), `IEnumerable` + `yield return` |
| 06 | Classes and dataclasses | `__init__`, `__repr__`, `@property`, inheritance, `@dataclass`, dunder methods | model `Vehicle`/`Position`; sort by field | classes, `record`, properties |
| 07 | Exceptions | `try/except/else/finally`, custom exceptions, `raise from`, EAFP vs LBYL | validate input; build an error hierarchy | `try/catch/finally`, custom exceptions |
| 08 | Files and JSON | `pathlib`, `open`, `with`, `json`, `csv` | read CSV, write JSON, handle a missing file | `using`, `System.IO`, `System.Text.Json` |
| 09 | Modules and packages | `import`, `__init__.py`, `__name__ == "__main__"`, relative imports, `pip` | split a script into a package | namespaces, assemblies, NuGet |
| 10 | Async basics | `async/await`, `asyncio.gather`, tasks | fetch N simulated resources concurrently | `async/await`, `Task.WhenAll` |
| 11 | Type hints | annotations, `Optional`, `list[int]`, `TypedDict`, `Protocol`, `mypy` | annotate code from earlier lessons | generics, interfaces, nullable reference types |

### Final mini-project: `final_project/` (GPS / fleet)

Uses everything learned, in a business domain I already know well:

## 8. Working conventions

- **Commits:** small and descriptive, in the `type: message` style (`feat`, `fix`, `docs`, `test`, `chore`).
- **Branches:** committing straight to `main` is fine for solo study. Optional: one branch per phase, merged at the end.
- **Golden rule:** never look at a solution before trying. If stuck for more than 30 minutes, write the question down, move on, and come back later.
- **Learning diary:** a `NOTES.md` file with 2 or 3 lines per lesson: what surprised me, what differs from C#. Written in English.
- **Suggested pace:** 30 to 60 minutes a day, one lesson every 2 or 3 days. Consistency beats marathons.

## 11. Risks and how to avoid them

| Risk | Mitigation |
|---|---|
| Losing momentum for lack of time | Short lessons; minimum goal of 3 sessions a week |
| Writing Python "with a C# accent" (too many classes, getters/setters) | A "Pitfalls" section in each lesson; prefer functions and dataclasses |
| Spending weeks on the skeleton instead of studying | Phase 1 limits the runner to the minimum; sophistication comes later |
| Skipping tests "because it works" | The runner only marks a lesson completed when tests are green |
